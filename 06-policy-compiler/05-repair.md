# Lesson 5: Repair

## Overview

A rule marked `REVIEW` can be rewritten by the compiler, using the examples the
judge got wrong. The important part is how we decide whether the rewrite is any
better.

### What you will learn

- How to feed failures back to a model
- Why old and new criteria are compared on **fresh** tests
- Why even that comparison is a little optimistic

---

## The rewrite

For each `REVIEW` rule, the prompt includes the current criterion, up to three
violations it missed, and up to three compliant examples it flagged. It asks for
a rewrite "without becoming vague":

```python
def step_repair(compiler, judge, entries, args):
    print(f"\n{'=' * 78}\nSTEP 5: REPAIR (compared on fresh tests)\n{'=' * 78}")
    for e in entries:
        if e.get("status") != "REVIEW":
            continue
        ev = e["eval"]
        hint = ("\n\nThe current criterion is:\n" + e["criterion"] +
                "\nAn AI judge using it made mistakes.")
        if ev["missed"]:
            hint += "\nViolations it MISSED:\n" + "\n".join(f"- {t[:250]}" for t in ev["missed"][:3])
        if ev["false_flags"]:
            hint += "\nCompliant examples it WRONGLY FLAGGED:\n" + "\n".join(f"- {t[:250]}" for t in ev["false_flags"][:3])
        hint += "\nRewrite the criterion to fix these mistakes without becoming vague."
        new_crit = draft_criterion(compiler, e["rule"], e["gate"], hint)
        if not new_crit or new_crit == e["criterion"]:
            print(f"{e['id']} no new criterion produced")
            continue
        ok2 = gen_tests(compiler, e["rule"], e["gate"], True, args.tests)
        bad2 = gen_tests(compiler, e["rule"], e["gate"], False, args.tests)
        if len(ok2) < 2 or len(bad2) < 2:
            print(f"{e['id']} too few fresh tests to compare, keeping the original")
            continue
        old_e = evaluate(judge, e["criterion"], ok2, bad2)
        new_e = evaluate(judge, new_crit, ok2, bad2)
        print(f"{e['id']} old: {line(old_e)}\n{'':<4} new: {line(new_e)}")
        if score(new_e) > score(old_e):
            e.update(criterion=new_crit, eval=new_e, tests_ok=ok2, tests_bad=bad2, repaired=True)
            e["status"] = status(new_e, args)
            print(f"{'':<4} keeping the rewrite  ->  {e['status']}\n{'':<4} {new_crit}")
        else:
            print(f"{'':<4} rewrite did not beat the original on fresh tests, keeping the original")
```

## Why fresh tests

If we compared old and new on the tests the rewrite was built from, the rewrite
could win just by fitting those examples. So we write **new** tests, score both
criteria on them, and keep the rewrite only if its score (recall minus
false-positive rate) is higher.

Two cautions, both worth saying out loud:

- Choosing the better of old and new on the same fresh tests slightly flatters
  the winner. Treat the winning numbers as optimistic
- A rewrite can win by getting stricter, which costs more false positives. The
  score counts both

```

```
